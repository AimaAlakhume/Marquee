# Marquee — submission contents

An AI agent that turns a plain-sentence request into something to watch, built for the
BrainStation AI Certification final project (Option 3: AI Agent).

**What ships:** a Chrome extension that runs on top of the real Disney+. No backend, no API
key, no network call at runtime. Parsing, retrieval, ranking and every guardrail happen in the
browser from the files in this ZIP.

**Where a model is and is not involved** — worth reading before the rest:

- **At runtime: none.** The shipped extension calls no model and holds no key. `src/agent.js`
  is deterministic code. The drawer badge says `local mode` and the trace labels the ranking
  method, so the interface never implies a model answered when one did not.
- **At build time: yes, and it is written down.** A large language model (Claude) wrote the
  `energy`, `warmth` and tone-tag values for the 115 audited titles, which were then reviewed
  by hand; and produced the four frozen parses in `data/cached_runs.json`. The other 200
  titles' tone layer comes from rules in `build/derive_tone.py`, not from a model.
- **Designed for, not wired up:** `run()` in `src/agent.js` takes an optional `llm` adapter
  with a `parse` and a `rerank` hook, and degrades to the deterministic core when it returns
  nothing. That is the seam a live model would attach to. Nothing is attached today.

## Files

| Path | What it is |
|---|---|
| `src/agent.js` | The whole agent: parse, clarify, retrieve, rank, validate, explain, refine. No DOM, no network. The page and the eval harness both import this file, so the demo and the numbers come from the same code. |
| `extension/panel.js` | The content script: reads the host page, hosts the concierge, injects the row. |
| `extension/panel.css`, `extension/manifest.json` | Styling and the MV3 manifest. |
| `extension/data.js` | Catalogue, profiles, quiz and cached runs, generated by `build/build_extension.py`. |
| `build/seed_catalog.py` | Builds `data/catalog.json` from a hand-curated title list, including the derived tone layer. |
| `build/run_evals.mjs` | The eval harness. `node build/run_evals.mjs` prints the pass table and writes `data/eval_results.json`. |
| `build/merge_catalog.py` | Merges harvested titles into the catalogue, keeping the audited tier intact. |
| `build/test_extension.py` | Drives the extension against a mock page: row detection, injection, quiz, guardrails. |
| `build/check_copy.py` | Spelling, grammar and readability over everything a person reads. |
| `data/catalog.json` | 315 titles in two tiers: 115 audited (tone layer written and checked by hand) and 200 derived from the live provider listing by `build/derive_tone.py`. |
| `data/profiles.json` | Three households, with histories, affinities, negative signals and hard filters. |
| `data/eval_set.json` | Thirty-nine cases with machine-checkable expectations. |
| `data/eval_results.json` | The recorded run. |
| `data/cached_runs.json` | Four model outputs produced at build time and frozen. Read, never generated, at runtime. |
| `docs/iteration_log.md` | Every failure observed and what changed because of it. |
| `docs/prompts.md` | The two model prompts, verbatim. |
| `docs/Marquee_AI_Design_Canvas.pdf` | The design canvas, one page. |
| `deck/Marquee_backup_demo.mp4` | 45-second recorded walkthrough, in case the live demo will not cooperate. |


## Reproducing the numbers

```
python3 build/build_extension.py   # rebuild extension/agent.js and extension/data.js
node     build/run_evals.mjs       # 39/39
python3 build/test_extension.py    # drives the extension against a mock page
```

`src/agent.js` is the source of truth; `build/build_extension.py` copies it to
`extension/agent.js` unchanged, so the demo and the eval numbers come from the same file.

## Honest limits

The catalogue is 315 titles, not a feed: the real service carries 5,297 in the US. Watch
histories are synthetic. The `energy` and `warmth` values are not official metadata — they are
handwritten for the audited 115 and rule-derived for the other 200.
